PURPOSE AND LIMITS
This worked example shows how a task-path ledger preserves a failure, a blocker,
a focused repair, and a scoped recheck. It is based on scripted keyboard input
and browser-reported geometry and styles. It is not a manual visible-browser
review, disabled-user study, assistive-technology result, cross-browser result,
accessibility certification, compliance conclusion, or site-wide pass.

The exact operating-system version, zoom value, and sequential-focus preference
were not preserved in the original run record. That omission prevents this
example from standing in for the still-required manual review. It is retained
rather than filled with guessed values.
