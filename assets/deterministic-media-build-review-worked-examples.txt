DETERMINISTIC MEDIA BUILD REVIEW — TWO WORKED SYNTHETIC EXAMPLES
Original method examples by Alfred

PURPOSE
These fictional records show how a matching media artifact can still be held for
repair, and how a harmless-looking environment change can block a byte-identity
claim without proving that the decoded media changed.

Neither example describes a real build, account, transfer, upload, destination,
publication, audience, customer, metric, revenue, or result. All candidate names,
source labels, toolchain labels, digests, routes, and observations are synthetic.
The placeholder identities are deliberately non-computable labels; they are not
presented as cryptographic digests of real files.

E. HONEST NEXT DECISION

Rejected shortcut:
Ignore the timestamp field after seeing the mismatch and call the build deterministic.

Why it is rejected:
The original rule covered the complete file. Relaxing it after observation would
turn a predeclared test into a post-hoc exception. It would also leave untested
whether the creation-time field is the only difference.

Eligible next paths:

PATH 1 — CONTROL THE FIELD
Create EXAMPLE-CLAIM-TIMESTAMP-R4 before rebuilding. Pin or omit the creation-time
field through a documented setting, explain why that field is non-semantic for the
release, and rerun two independent clean builds under the new declared boundary.

PATH 2 — DEFINE A CANONICAL REPRESENTATION
Create EXAMPLE-CLAIM-TIMESTAMP-R4 before rebuilding. Specify exactly which decoded
frames, audio samples, caption data, and required semantic metadata are compared;
identify which container fields are excluded and why; implement and identify the
comparison; then test it without changing the rule after observation.

Neither path may erase required caption, color, orientation, attribution, rights,
or provenance information merely to obtain a stable result.

CROSS-EXAMPLE REVIEW
======================================================================

Example 1 demonstrates:
- source admission can PASS;
- complete-file identity can MATCH;
- picture and audio can PASS;
- caption and accessibility lanes can FAIL;
- the only truthful release decision can still be HOLD FOR REPAIR.

Example 2 demonstrates:
- a comparison rule can be predeclared yet still rest on an incomplete environment
  boundary;
- complete-file identities can MISMATCH because ambient metadata changed;
- an informal perceptual observation cannot retroactively become the comparison;
- the honest next step is a new claim revision, not a post-hoc exception.

For both examples:
- local identity is not destination-rendition evidence;
- a transfer response would not prove visibility;
- private or unlisted state would not prove public availability;
- public state remains NOT PUBLIC;
- audience response remains NOT_TESTED;
- no real-world result is claimed.

COMPLETION BOUNDARY
These examples test the worksheet's state-separation behavior with fictional data.
They do not validate a build system, encoder, renderer, media candidate, destination,
publication workflow, accessibility outcome, rights position, or safety result. A
real review must identify its actual inputs, toolchain, environment, comparison,
artifacts, evidence, authority, and affected review lanes.
